# GOOD HUMAN! — 05 孫女小米：兔兔玩具替身戰鬥系統

版本：v1.0｜用途：交給本機 Claude Code 進行 Godot 專案整合｜語言：繁體中文

## 0. 不可變更的角色設定（P0）

- **小米原始形象是唯一外觀基準**：深棕／黑色高丸子頭與散落瀏海、黃色連帽外套、藍色牛仔吊帶短褲、藍綠色探險背包（兔兔吊飾）、襪子及運動鞋。**不得**改成金髮、粉紅公主裝、肌肉變身、戰鬥服，也不得任意更改服裝配色。
- 年齡設定 10 歲，活潑、好奇、喜歡探險、攝影、收集與觀察。日常活動仍是狗狗陪伴小米散步。
- 戰鬥只有**兔兔玩具機器人**承擔被鎖定、碰撞傷害、受擊、擊倒與敗退；小米本人**沒有**敵方 Hurtbox、傷害動畫、流血或住院動畫。
- 戰鬥畫面不得以「兒童被打」為笑點；幽默來源是玩具物理、彈簧、泡泡、積木與成年對手的誇張反應。
- 本文件是設計規格；**先讀取現有專案**，不得假設已存在指定類別、節點或檔案。以下路徑及介面為建議，需按現有架構調整。

## 1. 設計目標與非目標

### 目標
1. 不更改既有狗狗第一視角／低視角、戰鬥不切場景、QTE 格擋、主人技能排序、搜打撤與武器／裝備循環。
2. 戰鬥中將「主人戰鬥實體」替換為兔兔機器人；小米在安全區指揮或離開鏡頭。
3. 機器人承擔 HP（UI 命名為「電量／耐久」）、狀態、攻擊與戰敗後果。
4. 使用可替換玩具模組讓探索搜刮有意義。
5. 優先交付可玩的 Godot MVP，暫用簡單替代模型也可以。

### 非目標
- 不重構整個戰鬥系統、不一次做所有技能／全部 UI、不要求先完成高精度 3D 模型。
- 不增加兒童攻擊或受傷判定，不讓小米進入近戰交戰位置。

## 2. 場景流程與狀態機

建議狀態：`EXPLORE → ENCOUNTER → DEPLOYING → COMBAT → VICTORY / DEFEAT → EXTRACT / EXPLORE`。

| 狀態 | 小米 | 兔兔機器人 | 狗狗／鏡頭 |
|---|---|---|---|
| EXPLORE | 原外觀跟隨散步 | 收納在背包／未生成 | 維持既有探索視角 |
| ENCOUNTER | 前往經驗證安全位置；若無位置則直接移出交戰區並隱藏 | 準備生成 | 不切換場景 |
| DEPLOYING | 播放遙控器／指揮短動畫 | 在戰鬥位置生成，進入戰鬥代理 | 鏡頭轉向代理與對手 |
| COMBAT | 只作背景指揮，不可受擊或被鎖定 | 唯一可受擊的己方主人代理 | 沿用 QTE／技能序列 |
| VICTORY | 歡呼 | 慶祝並收納 | 回到探索 |
| DEFEAT | 安全撤離；無倒地／受傷鏡頭 | 沒電關機、可修復的玩具散件演出 | 按既有撤退與掉裝規則結算 |

**競態與例外**：在 `ENCOUNTER/DEPLOYING` 期間先關閉敵人對小米的鎖定與傷害，避免部署動畫空窗；若安全位置不可達、代理生成失敗或鏡頭失效，立即啟用安全 fallback（小米退出交戰區、取消戰鬥或安全撤離），不得讓敵人改鎖定小米。戰鬥結束後清理代理、鎖定引用、訊號與臨時碰撞狀態。

## 3. 戰鬥代理的介面契約

建議透過現有 `Combatant`／`Owner`／`BattleActor` 抽象接入，不要在所有敵人 AI 中寫 `if owner == Xiaomi`。若現有專案無抽象，先以小型 Adapter 包裝。

```gdscript
# 示意介面；按現有 Godot 版本、架構與命名實作
class_name CombatProxyAdapter
extends Node

signal proxy_defeated
signal proxy_damaged(amount: float)

@export var max_durability: float = 100.0
var durability: float = 100.0
var active: bool = false

func receive_damage(amount: float, source: Node = null) -> void:
    if not active or amount <= 0.0:
        return
    durability = maxf(0.0, durability - amount)
    proxy_damaged.emit(amount)
    if durability <= 0.0:
        active = false
        proxy_defeated.emit()
```

- `owner_id = xiaomi` 是角色識別；`combat_actor` 指向兔兔代理，不是小米節點。
- **鎖定白名單**：敵人只可鎖定 `combat_actor`，不可鎖定 `XiaomiVisual`、小米的跟隨代理、其影子或碰撞體。
- **碰撞分層**：小米可保留探索用環境碰撞，但不可進入敵方武器 Hurtbox/Hitbox 可命中的層；兔兔擁有戰鬥 Hitbox、Hurtbox 和必要的實體碰撞。避免把所有碰撞關掉而造成穿模。
- **傷害來源與歸屬**：兔兔攻擊應計入小米所屬的隊伍與戰鬥結算，並保留狗狗 QTE 支援的歸屬。
- **同步**：部署／收納期間避免敵人鎖定空引用；使用現有狀態機的原子切換或可驗證的安全順序。

## 4. MVP 技能與搞笑演出

| 技能 | 類型 | MVP 實作 | 表現規則 |
|---|---|---|---|
| 彈簧愛心拳 | 基礎攻擊 | 單體傷害 + 小幅擊退 | 兔兔彈簧拳套；不是真實肉搏 |
| 兔兔翻滾 | 移動／閃避 | 短距位移，短暫減傷或無敵窗（依既有平衡） | 玩具輪子與暈眩星星 |
| 積木雨 | 控場 | 小範圍減速或短暫失衡 | 成年敵人踩到積木滑步，無血腥 |
| 超級兔兔 | 必殺技，第二階段 | 暫時大型機甲外觀／範圍擊退 | 只放大玩具，不變身小米 |

**第一輪只做**「彈簧愛心拳 + 兔兔翻滾 + 敗退關機」，其餘做接口和佔位資料；沿用既有主人技能排序、冷卻和戰鬥數值，不另外創建平行技能系統。

## 5. 搜打撤、裝備與經濟

- 可搜尋物：彈簧、電池、齒輪、玩具馬達、塑膠護甲、遙控模組、玩具拳套。
- 裝備欄優先映射既有武器／防具欄：拳套=武器；外殼=防具；電池=消耗品／耐久修復；控制晶片=特殊模組。
- 戰敗：代理沒電／故障；按現有規則掉落**可掉落**的玩具裝備；小米本人不住院，改成「兔兔維修中」的同等冷卻／代價。
- 掉落規則、保護欄、經濟成本與其他主人保持可比較，不額外免罰。
- 後續可開啟模組差異（擊退、控場、續航），但 MVP 先以 2–3 件測試裝備驗證掉落與回收。

## 6. 視覺資產規格

### 小米（沿用既有模型）
- **直接使用現有小米角色素材**，不重新生成替代角色、不改色、不替換髮型或衣服。
- 若需新增動畫，只新增：按遙控器、歡呼、收納兔兔、安全撤離；不新增被打、受傷、死亡動畫。

### 兔兔玩具機器人（新增）
- 造型：粉色／奶白色、圓潤、兔耳、可伸縮彈簧拳套、玩具塑膠與簡單機械關節；與小米原本背包兔兔吊飾呼應，但不替代她的藍綠探險背包。
- 風格：Stylized 3D，與現有主人角色同世界；避免寫實金屬武器、血腥與威嚇外觀。
- Godot 手機基準：先以簡單低面數代理模型測試，正式模型按手機場景 profiling 決定三角面數與貼圖尺寸；建議 GLB/glTF 2.0、可分離的耳朵、拳套、機身與輪子。
- 特效：泡泡、愛心、星星、彈簧、紙屑；以 Godot 可控的粒子／shader 實現，不用大張全螢幕影片。

## 7. Godot 專案落地工作流（Claude Code 執行）

### Phase 0 — 專案盤點（必做）
1. 列出 Godot 版本、專案場景入口、玩家狗狗控制器、主人角色、戰鬥管理、AI 鎖定、傷害判定、QTE、裝備／掉落／存檔相關實際路徑。
2. 確認目前是否已有小米模型、動畫、資源 ID、戰鬥代理機制；**不得覆寫原始角色資產**。
3. 輸出 `XIAOMI_INTEGRATION_AUDIT.md`：可重用系統、需要擴充的點、風險與預計改動檔案。

### Phase 1 — 最小可玩閉環
1. 實作可部署的兔兔替身（先用 placeholder mesh）。
2. 敵方 AI 攻擊目標只會是兔兔；小米移至安全位置／安全隱藏。
3. 沿用原本戰鬥畫面、狗狗視角與 QTE，兔兔能受擊、格擋／擊退、失敗。
4. 加入關機與安全撤離，確認不會進入主人住院的兒童動畫。
5. 新增自動化／手動驗證場景。

### Phase 2 — 技能、裝備與存檔
1. 接上彈簧拳、翻滾、技能排序。
2. 接上 2–3 件玩具模組與戰敗掉落／維修冷卻。
3. 驗證重開遊戲後角色與裝備資料不遺失，並確認其他主人不受影響。

### Phase 3 — 美術與優化
1. 使用既有小米形象，獨立製作兔兔模型及動畫。
2. 補上玩具特效、鏡頭切換與低視角遮擋修正。
3. 在實機驗證效能，必要時提供 LOD、粒子數量與貼圖壓縮策略。

## 8. 驗收測試（必須通過）

### P0 安全與正確性
- [ ] 小米外觀與既有素材一致：深色丸子頭、黃色外套、牛仔吊帶短褲、藍綠背包，無任何粉色公主裝替換。
- [ ] 任何敵方攻擊（近戰、遠程、AOE、碰撞、陷阱、持續傷害）均**不能**對小米造成傷害、受擊動畫或鎖定。
- [ ] 部署中、兔兔故障、目標切換、讀檔與撤退過程均不會暴露小米為有效敵方目標。
- [ ] 戰鬥期間兔兔是唯一代表小米承傷的戰鬥單位，敵人對其傷害與控制可正常結算。
- [ ] 小​​米敗退時沒有住院、倒地、流血或受傷演出；只顯示兔兔關機與維修。
- [ ] 不切場景；狗狗視角、QTE、戰鬥技能流程不回歸失效。

### 功能與品質
- [ ] 兔兔的基本攻擊、受擊、倒地／關機、撤離可完整跑通。
- [ ] 搜尋到的玩具模組可裝備，戰敗時依原規則掉落，維修冷卻生效。
- [ ] 其他主人仍正常進入戰鬥、受傷、結算。
- [ ] 存檔／讀檔、快速連續遭遇、敵人消失、玩家離開區域、代理生成失敗均不產生卡死或空引用。
- [ ] 兔兔與敵人有實體碰撞；小米與狗狗探索碰撞維持正常。
